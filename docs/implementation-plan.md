# 智能制造桌面 Agent 实施计划

本计划落实 [需求文档](requirements.md) 和 [架构设计](architecture.md)，以可独立验收的功能阶段推进。首版 Windows 优先，业务服务支持本机和内网服务器两种部署。各阶段关联的需求、代码和验收状态在 [追踪表](traceability.md) 维护，开发遵循 [Harness 工程约束](engineering-constraints.md)。

需求基线 1.0 已由用户确认，M0 的初始需求与文档检查设施已建立。当前 M1-T01 至 M1-T07 已验证，包含真实 Windows CI 与现有合并策略审计，下一任务为 T08 集成验收，后续按 [8 张阶段任务卡](tasks/m1/README.md) 和 [任务清单](tasks/m1/tasks.json) 推进。main 必要检查合并限制未配置，独立保留在 HAR-009。产品功能与工程设施的实现状态分别记录，不因骨架与契约已建立而提前计为完整产品完成。

按可运行的里程碑组织交付：

| 顺序 | 对应阶段 | 可检查的交付结果 |
| --- | --- | --- |
| 1 | M1 | 开发骨架可运行，契约与检查入口建立 |
| 2 | M2 和 M3 | Windows 本机模式能完成一次模拟排查，展示进度、证据和历史 |
| 3 | M4 | 同一个客户端连接工厂服务器，验证真实模型、身份权限和双模式行为 |
| 4 | M5 | 接入首个现场只读连接器，再按前提逐项开放处置 |
| 5 | M6 | 验证安装包、升级和备份恢复，形成可交付版本 |

M1 的首批工作是检查开发环境和现有目录、建立前后端骨架、定义最小 API 与事件契约、建立类型与文档检查。开发模式下可以打开基础窗口并读取 Python 健康状态；完整排查界面和正式安装包分别在后续阶段验收。M1 重点关联 REQ-001 至 REQ-003 的技术基础、REQ-005 的契约，以及 HAR-003 至 HAR-005、HAR-009。

每个里程碑提供运行方式、验证结果、实现位置和遗留项，并更新追踪表。性能门槛、现场连接器和服务器身份来源在各自需要时明确，不阻碍 M1 的骨架工作。

## 0 需求与工程基线

维护需求编号、来源、优先级、验收标准和待确定事项；区分用户确认、推导建议与技术方案。建立简短开发入口和文档检查，后续功能变更按需求切片，完成时填写实现与证据。

交付与验收：

- 产品需求和工程约束全部进入追踪表，设计文档不被当作产品实现证据。
- `python scripts/check_project_docs.py` 可检查编号、追踪、状态和本地引用，并能识别故意构造的错误样例。
- 当前未实现的类型、边界、模型评测、桌面测试和 CI 检查保持未开始状态。

## 1 统一契约与目录骨架

本阶段拆分为 M1-T01 至 M1-T08，依次覆盖工程质量基础、服务骨架、契约、桌面骨架、桥接、产品检查接入、CI 和集成验收。依赖、逐项 AC 和交付证据以 [任务卡](tasks/m1/README.md) 为准，统一检查见 [质量工作流](quality-workflow.md)。

建立桌面、Python 服务、生成客户端和契约目录。定义会话、消息、任务、事件、工具结果、处置提案和错误模型；约定 API 版本、部署标识、幂等键与分页方式。定义模型、工具、存储和凭据接口，保留现有 demo。

交付与验收：

- TypeScript 类型检查和 Python 基础检查可运行。
- Pydantic 生成 OpenAPI，TypeScript 客户端由契约生成，生成结果可检查一致性。
- 契约示例明确成功、失败、取消、待核对以及不兼容版本的行为。
- 建立依赖锁定、产品统一检查入口、导入边界检查，并接入实际代码托管平台的 CI；尚未配置的检查明确标记未接入。

## 2 任务核心与 mock 排查

实现 SQLite 存储、迁移、会话和任务 API、数据库排队、执行器、事件落库、SSE、取消与恢复判定。将现有四类故障数据转换成测试夹具，mock 工具不依赖旧全局注册表。开发期间服务仅监听回环地址并认证，不将此阶段作为可用的远程生产服务。

交付与验收：

- 一次提交立即返回任务编号，执行过程可以实时读取。
- 相同幂等键不创建重复任务，不同请求复用同一键得到冲突。
- 同一会话不能并发创建两个活跃任务，数据库事务保证限制。
- 断开 SSE 后执行继续；使用游标重连无遗漏，重复事件可去重。
- 用户取消后不再调度新工具，在途动作状态如实保留。
- 模拟服务中断后进入待恢复状态，未确认的动作不会自动重做。

## 3 Windows 桌面与本机部署

实现 Electron 生命周期、preload 桥接、连接配置、Python 服务管理和 React 主界面。提供会话列表、消息、任务进度、证据详情和本机设置，主进程统一管理网络与事件订阅。

交付与验收：

- 安装后的应用能自动启动随包 Python 服务，不依赖开发机 Python、Node.js 或项目工作目录。
- 随机端口、启动握手、认证、单实例和后台服务退出机制可验证。
- 关闭窗口到托盘后任务继续；明确退出后正确收尾，不遗留后台服务。
- 启动失败、模型未配置、网络断开和任务失败有对应的界面。
- 模型输出无法调用任意 IPC、执行脚本或读取任意本地文件。
- 记录实际目标 Windows 版本和 CPU 架构，分别保留开发模式与安装包验证证据。

## 4 内网服务器与双模式验收

实现 PostgreSQL 存储适配、服务器部署配置、认证会话、工作区权限、HTTPS 入口与连接切换。增加真实模型适配器，保留显式 mock 模式，模型不可用时返回真实错误。界面与业务流程共用，不复制一套服务器专属功能。

交付与验收：

- 多个客户端可连接同一服务器，用户与工作区的资源权限可验证。
- 账号认证、令牌过期和注销生效，服务不能匿名暴露业务接口。
- 客户端关闭不取消服务器任务，重新打开可读取进度和最终结果。
- 本机与服务器切换时，旧事件和缓存不会进入新工作区。
- SQLite 和 PostgreSQL 分别通过事务、迁移、幂等和并发集成测试。
- 内网代理不会缓冲 SSE；网络恢复后的历史补发可用。
- 工具在服务所在主机执行，界面明确说明文件上传与设备可达范围。
- 真实模型的行为评测与 mock 回归分开记录，权限、证据引用、异常与预算场景有明确结果。

完成本阶段后交付支持两种部署的诊断版本。处置按钮仅允许模拟执行，真实写操作尚不开放。

## 5 工业连接器与处置闭环

先选择一个现场可验证的只读连接器，再实现具体写操作的提案、确认、资源锁、执行和结果核对。优先使用已有工业平台 API，不让 Agent 直接生成任意系统命令。为每个真实连接器编写参数、权限、超时和幂等契约。

交付与验收：

- 日志和指标有真实来源与时间信息，模型结论能引用证据。
- 模型或前端不能绕过工具权限与后端确认策略。
- 重复确认只执行一次提案；参数改变使已有确认失效。
- 取消、超时和中断场景下，未知结果不会被显示为动作成功。
- 同一设备的冲突写操作被串行化，结果未知时阻断后续冲突动作。
- 设备操作完成后独立检查是否恢复，不将接口返回成功等同故障已解决。

## 6 发布与运维验收

在干净 Windows 环境验证安装包、本机数据目录、带数据库的升级和卸载后的数据保留策略。验证 Windows/Linux 服务器部署、HTTPS、数据库与附件备份恢复、日志脱敏和版本兼容。

交付与验收：

- 安装包与服务器包有明确版本、依赖锁定、校验信息和部署说明。
- 本机 SQLite 一致性备份与服务器 PostgreSQL、附件的恢复演练通过。
- 客户端和服务端不兼容时明确提示，不能带着不匹配的契约执行任务。
- 模型、网络和工具故障的错误信息可定位，日志不包含凭据。
- 测量真实启动时间、事件延迟、内存和任务容量，再调整默认并发与预算。

## 7 后续扩展

按实际使用需求评估 macOS/Linux 桌面构建、企业 OIDC、MCP、知识检索、案例库、边缘连接器和独立 worker。需要多副本或更多并发时，先验证任务领取租约、资源锁、重复投递和故障恢复，再引入外部队列或更多服务。
